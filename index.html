#1 Fundamental Theory Q&A

1

Apa Aplikasi yang Dibuat?

Sebuah Aplikasi POS (Point of Sales) bernama Lunacaffe. Aplikasi ini membagi pengalaman layarnya menjadi dua mode independen: Fitur Self-Service untuk pelanggan (mencari kopi, menambah keranjang pesanan, dan mencetak tiket antrean secara otonom) dan fitur Managerial khusus bagi pegawai di belakang layar untuk menuntaskan antrean (*Order Queue*) ke pelanggan.

2

Siapa Saja User/Aktornya?

Terdapat 3 ruang lingkup Hak Asasi Pengguna:

  • Pelanggan Kiosk: Masuk bebas (*guest*), menembus layar utama keranjang belanja secara langsung.
  • Kasir (Regular Staff): Membutuhkan verifikasi kata sandi di Portal. Akses dibatasi hanya pada transaksi operasional pelanggan.
  • Admin (Super Staff): Memiliki otoritas tertinggi (*Root*). Mampu menambah menu, ubah harga, dan mendaftarkan pemecatan Kasir!
3

Bagaimana Struktur Abstrak Kelas (Silsilah)?

Pemrograman Java kami membagi genetik (Turunan) aktor seperti skema akar pohon untuk mencapai ke-efisienan kode tertinggi *(Don't Repeat Yourself)*:

👑 Induk Tertinggi: abstract class Aktor
Menelurkan kewajiban mutlak lewat abstract method masukSistem(). Tak satupun turunan bisa mengelak!
- Anak Jalur 1: class Pembeli extends Aktor
Membentuk aktor kasual tanpa jejak keamanan di RAM.
- Anak Jalur 2: class Pegawai extends Aktor
Mewarisi genetik rahasia lewat enkapsulasi atribut username dan password.
├─ Cucu Sub-Pegawai A: class Kasir
└─ Cucu Sub-Pegawai B: class Admin

#3 Alur Logika Eksekusi Aplikasi

#4 Anatomi Teknis Penggerak

🔌 Organ Arsitektur M-V-C

Kode proyek kami tidak ditulis sembarangan atau bergerombol panjang di satu kelas Main.java. Lunacaffe memilah organ tubuh aplikasi ke dalam bentuk paket (*Package*) bersih mengikuti metode *Best-Practice* Model-View-Controller:

🤖
M - Model

com.lunacaffe.model.*

Struktur otak OOP. Di dalamnya tumbuh konstruktor kelas entitas. Data tidak mengalir jika bentuk *Class Menu* dan *Pembeli* belum dipahat di sini.

🖼️
V - View

com.lunacaffe.view.*

Lukisan estetika. Seluruh panel berbasis komponen antarmuka GUI (Java Swing FlatLaf) bertugas mendesain bingkai tanpa menyentuh database sedikit pun.

🚀
C - Controller (DAO)

com.lunacaffe.dao.*

Sang Mandor. Menangkap perintah dari View (Misal: Kasir teken Enter Login), dan DAO mengirim bahasanya agar diolah di mesin SQL dan melaporkan kembali validasinya (True/False).

🗄️ Relasional Database Schema (SQLite Offline)

Kami memilih menginjeksi mesin SQLite karena dia mampu membuat program ini berdiri *(Stand-Alone)* di laptop siapapun tanpa terhubung internet atau menyalakan XAMPP Server!

🗂️ Table 1: users
  • id (PK - Varchar)
  • nama (Varchar)
  • username (Varchar, Unique)
  • password (Varchar)
  • role (Enum: admin/kasir)
🗂️ Table 2: menus
  • id (PK - Varchar)
  • nama (Varchar), kategori (Varchar)
  • harga (Real), stok (Integer)
  • image_path (Varchar | Icon Emojis)
⛓️ Table 3 & 4: orders + order_details (Transaksi Relasional)
  • Data Bon/Resi Utuh:
  • id (PK - ex: ORD-2026-001)
  • nama_pelanggan, total_harga
  • status (Menunggu / Selesai)
  • Data Rincian Per Tipe Beli:
  • id (Auto PK)
  • order_id (FK ke tabel Orders)
  • menu_id (FK ke tabel Menus)
  • qty (Jmlh), subtotal

#6 Pembuktian Fundamental PBO

Bukti otentik bahwa kelompok kami mampu mendaratkan hukum teori murni ke tatanan program hidup. Silakan bongkar akordeon pilar di bawah dengan me-kliknya!

Pembangun bangunan tidak akan menuang semen tanpa denah arsitek. Dalam OOP, class adalah cetak biru itu. Kami tidak menciptakan Menu di sembarang tempat, tapi membungkus kerangkanya resmi.

public class Menu {
    private String idMenu;
    private String namaMenu;
    private double harga;
    
    // Konstruktor Pembentuk Kehidupan
    public Menu(String id, String nm, double hg) {
        this.idMenu = id;
        this.namaMenu = nm;
        this.harga = hg;
    }
}

Denah dihidupkan dengan kata kunci new. Object adalah bentuk wujud yang menghisap porsi memori RAM komputasi. Ketika pembeli masuk *CustomerPanel*, wujud Pesanan dilahirkan asisten kami.

// Berada di dalam class CustomerPanel.java:
private void initNewPesanan() {
    // Menciptakan object nyata Pesanan di memori Aplikasi
    // Meminta nama ("TEMP", "Guest", "Status Awal") ke Konstruktornya!
    currentPesanan = new Pesanan("TEMP_ID", "Guest", "Menunggu");
}

Menjaga privasi. Atribut di gembok paksa menggunakan private agar *Hacker* / kelas usil tidak bisa meng-edit harga sembarangan dari pintu depan. Komunikasi perdata wajib lewat Get/Set.

// Di class Pesanan.java
private double totalHarga; // Rahasia dan Gelap!

// Pintu Akses Tunggal Resmi (Public)
public void setTotalHarga(double tot) {
    if(tot >= 0) this.totalHarga = tot; // Aman & Validasi
}

public double getTotalHarga() { 
    return this.totalHarga; // Laporan sah 
}

Prinsip Don't Repeat Yourself (DRY). Kami mewariskan karakter dari `Pegawai` menggunakan extends ke anak turunannya agar tidak kepingkal-pingkal menulis berulang.

public class Admin extends Pegawai {
    // Admin secara magis punya variabel username dan password, 
    // meski di dalamnya terlihat kosong, gen-nya sudah diturunkan.
    
    public Admin(String nama, String username, String pass) {
        // Keyword super() menembak pelurunya langsung ke Rahim Bapaknya
        super(null, nama, username, pass, "admin"); 
    }
}

Berbeda perlakuan walau dipanggil dengan nama perintah yang sama (Metode *Overriding*). Fungsi masukSistem() menghasilkan pergerakan radikal di masing jiwa raga aktor!

// 1. DI CLASS PEMBELI:
@Override
public void masukSistem() {
    System.out.println("Pembeli dilarikan ke Katalog Kopi Terbuka!");
}

// 2. DI CLASS PEGAWAI:
@Override
public void masukSistem() {
    System.out.println("Peringatan! Pegawai WAJIB disaring Validasi Kata Sandi Database Dulu!");
}

Ide Abstrak tidak punya jasad. Kelas Aktor disegel dengan metode tak berisi agar dia mustahil wujud merdeka, dan malah memaksa seluruh anaknya memiliki rute masuk kerja mandiri.

public abstract class Aktor {
    
    // Ini bukan deklarasi panggil, melainkan Kontrak Hukum!
    // Memaksa siapa saja turunan Aktor wajib membuat "masukSistem()"!
    public abstract void masukSistem(); 
}

// Bukti: Jika Anda menulis 'Aktor x = new Aktor();' di NetBeans, 
// IDE Java akan komplain dan menggemakan ERROR warna merah! 
// "Aktor terlalu Gaib, dia hanya konsep!"

#7 Kompilasi Eksekusi Program (Run)

⚙️

Cara Membedah & Menjalankan LUNACAFFE di Dapur Lokal Anda

Proyek ini diawasi ketat oleh Apache Maven untuk automasi injeksi dependensi sehingga Anda tidak direpotkan dengan perpindahan raib *(Missing .JAR Library)*.

  1. Pastikan persenjataan utama JDK (Java Development Kit) 11 atau 17+ berada dalam perangkat Anda.
  2. Clone/Download Repositori ke dalam penyimpanan folder NetBeans atau IntelliJ Anda. Jangan dihambur asal-asalan.
  3. Bukalah direktori sebagai sebuah bingkai "Open Maven Project". Otomatisasi sinkronisasi pom.xml akan menurunkan modul magis FlatLaf 3.2.1 dan pelengkap sqlite-jdbc 3.42.
  4. Pergi menuju kelas muasal src/main/java/com/lunacaffe/Main.java lalu lepaskan pelatuk (Run File / Shift+F6).
  5. Pemberitahuan Aman! Begitu aplikasi menyala pertama kali, Modul DatabaseConnection.java akan membentuk lunacaffe.db file sendirian menempel pada pijakan direktori Anda, menyuntikkan Master Data dan Bibit Akun siap pakai secara ajaib!
